# "Hợp nhau" Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A shares an invite link, B sees an instant zodiac + life-path match, takes the existing test to unlock the personality part, and gets a full, shareable compatibility screen that lets B invite C.

**Architecture:** All scoring and copy selection are pure functions in `_lib/compat.ts` over a small `CompatPerson`. Invite data travels only in the URL: `?i=` carries base64url `{v,type,sign,lifePath}`, and the display name sits after `#` (`#n=`, plus `&m=` on pair links), so no server ever sees a name. The existing quiz page body moves into a reusable `PersonalDefinitionFlow` component that `/personal-definition/hop-nhau` mounts with the invite and B's pre-filled birth date. The app stays fully static: the OG image is a build-time `opengraph-image.tsx` with no request data.

**Tech Stack:** Next 16.2.9 App Router, React 19, Tailwind v4, Vitest 4 + Testing Library (jsdom). The repo is `personality_spec`, app in `web/`, branch `feature/personal-definition/ui`. Run commands from `web/`.

**Spec:** `docs/hop-nhau-spec.md` (decisions locked in its §7). Copy tables in spec §2 are the source of truth for every user-facing string in Tasks 1, 4, 5, 6.

## Global Constraints

- Paths below are relative to `web/app/personal-definition/` unless they start with `web/`.
- Weights are integer math: `total = clamp(round((4P + 3Z + 3L) / 10), 45, 100)`.
- Personality: S/N same +30, J/P same +20, T/F same +15, E/I different +20 / same +15, base +15.
- Zodiac: same sign 92, same element 88, Fire–Air or Earth–Water 80, other **65**.
- Life path: reduce 11→2, 22→4, 33→6 first; groups {1,5,7} {2,4,8} {3,6,9}; same 90, same group 85, different group **70**.
- Tiers: ≥90 "Cặp bài trùng", ≥80 "Hợp cạ", ≥70 "Bổ sung cho nhau", ≥60 "Cần thêm thời gian", else "Oan gia ngõ hẹp".
- Symmetric (`hop(A,B) = hop(B,A)`, including every chosen sentence) and deterministic (no `Math.random`, no time).
- Never put birth date, full name, school or answers in a URL, invite code, analytics event or log. The name only goes after `#`.
- New copy: no "MBTI" (say "nhóm tính cách"), no dashes `—` `–` ` - `, no "chia tay"/"định mệnh"/"số phận"/"xui"/"khắc", each line ≤ 90 characters, and no person's name inside a copy line.
- Route: `/personal-definition/hop-nhau`. Invite URL: `${origin}/personal-definition/hop-nhau?i=<code>[#n=<name>]`. Pair URL: `…?i=<codeA>&j=<codeB>[#n=<nameA>][&m=<nameB>]`.
- `track()` is a no-op (Q8). Events: `compat_invite_create`, `compat_invite_open`, `compat_partial_view`, `compat_test_start`, `compat_full_view`, `compat_share_click`, `compat_share_success`. Allowed props are only `tier`, `format`, `hidden_name`.
- Use existing tokens/patterns: inline-style theme colours, `TEMPERAMENTS[temperamentOf(type)].accent`, `poseForType(type)` for mascots, worker `Select` for date parts.
- Phase file budget: at most 4 new source files per phase. Tests, assets, and small wiring edits (≤ ~15 lines) to existing files are listed but not counted.
- Read `web/node_modules/next/dist/docs/` before Tasks 4 and 8 (Next 16 breaking changes, per `AGENTS.md`).

## Review Focus

1. **Invite link truncated by a chat app** (Zalo and Messenger cut long URLs): the landing must show the friendly error screen, never crash or show a stack. Pinned in Task 2 (`decodeInvite` on truncated codes) and Task 4 (screen test).
2. **Name with emoji, CJK, control characters, `#`/`&`/`=`, or 30+ characters in the hash:** renders as plain text, survives round-trip, and over-length or garbage is dropped to "Một người bạn". Pinned in Task 2 (`readHashNames`) and Task 4.
3. **Master numbers 22 vs 4 and 11 vs 22:** "cùng gốc số" note only when the roots match and the raw numbers differ; 11 vs 22 is "same group" (85) with no note. Pinned in Task 1.
4. **B taps "Quay lại" on the form inside the invite flow:** returns to the hop-nhau landing with the chosen date kept, not to the generic intro hero. Pinned in Task 3.
5. **B already has a result and opens a pair link (`?i=&j=`)** with one invalid half: show the error screen, not a half-filled compare. Pinned in Task 5.

      let h = 0x811c9dc5;
